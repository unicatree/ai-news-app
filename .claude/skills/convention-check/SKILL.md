# 커밋 전 코드 검토

커밋하기 전에 변경된 코드가 코딩 컨벤션을 지키는지, 코드 품질에 문제가 없는지 검토한다.
모든 안내는 한국어로 한다.

## 1. 변경된 코드 가져오기

현재 브랜치에서 변경된 코드를 모은다.

- `git branch --show-current`로 현재 브랜치를 확인한다.
- `git status --short`로 변경된 파일 목록을 확인한다.
- `git diff HEAD`로 아직 커밋하지 않은 변경(스테이징 여부와 무관)을 가져온다.
- 추적하지 않는 새 파일(`??`)은 diff에 나오지 않으므로 파일 내용을 직접 읽는다.
- 현재 브랜치가 `main`이 아니면 `git diff main...HEAD`로 이 브랜치에서 이미 커밋한 변경도 함께 검토한다.
- 변경된 코드가 없으면 "검토할 변경 사항이 없습니다."라고 알리고 끝낸다.

검토 대상은 **변경된 줄**이다. 변경되지 않은 기존 코드의 문제는 검토 결과에 넣지 않는다.

## 2. 규칙별로 검토하기

[conventions.md](conventions.md)를 읽고, 그 안의 규칙 하나하나를 기준으로 변경된 코드를 점검한다.
각 항목을 **통과** 또는 **개선필요**로 표시한다.

결과는 아래 형식의 표로 보여준다.

| 구분 | 항목 | 결과 | 위치 |
|---|---|---|---|
| 네이밍 | 변수명, 함수명 : 카멜 케이스 | ✅ 통과 | |
| 코드 품질 | console.log 제거 | ⚠️ 개선필요 | `src/app/api/news/fetch/route.ts:42` |

- 위치는 `파일경로:줄번호` 형식으로 적는다.
- 같은 항목에서 문제가 여러 곳이면 위치를 모두 적는다.
- 변경된 코드에 해당 규칙을 적용할 대상이 없으면(예: DB 조작 코드가 없음) **통과**로 표시하고 "해당 없음"이라고 덧붙인다.

## 3. 개선 방법 알려주기

**개선필요** 항목이 있으면 항목마다 다음을 알려준다.

- 무엇이 문제인지 한두 문장으로 설명
- 지금 코드와 고친 코드를 나란히 보여주는 예시

```ts
// 지금
const res = await db.insert(articles).values(item);

// 수정
try {
  const res = await db.insert(articles).values(item);
} catch (e) {
  return Response.json({ error: "뉴스를 저장하지 못했습니다." }, { status: 500 });
}
```

코드를 직접 고치지는 않는다. 사용자가 고쳐 달라고 요청할 때만 수정한다.

## 4. 모두 통과한 경우

모든 항목이 **통과**이면 표 아래에 다음 문구를 출력한다.

> 커밋 준비가 완료되었습니다.
