# 뉴스수집기 기능 개발 워크플로

뉴스수집기 앱에서 새 기능을 개발할 때 쓰는 명령이다. 아래 단계를 **순서대로** 진행한다.
모든 안내는 한국어로 한다.

브랜치이름: $ARGUMENTS

## 1. 현재 상태 확인

- `git status`와 `git branch --show-current`로 현재 브랜치와 작업 트리 상태를 확인한다.
- 현재 브랜치가 `main`이 아니면 **경고**를 보여준다(예: "⚠️ 현재 브랜치는 `xxx`입니다. main이 아닙니다.")
  그리고 main으로 이동할지 사용자에게 물어본다.
  - 이동하겠다고 하면 `git switch main`으로 이동한다.
  - 이동하지 않겠다고 하면 여기서 멈추고 이유를 안내한다.
- 커밋하지 않은 변경 사항이 있으면 목록을 보여주고 어떻게 할지(커밋, stash, 그대로 진행) 물어본다. 임의로 버리지 않는다.

## 2. 새 브랜치 만들기

- 브랜치이름(`$ARGUMENTS`)이 있으면 그 이름으로 `git switch -c <브랜치이름>`을 실행한다.
- 브랜치이름이 비어 있으면 어떤 기능을 개발할 것인지 물어본다.
  답을 받으면 **영어 소문자-하이픈 형식**(예: `category-management`, `save-all-news`)으로 브랜치이름을 제안하고, 사용자가 확인하면 만든다.
- 같은 이름의 브랜치가 이미 있으면 알려주고 다른 이름을 제안한다.

## 3. 개발 시작 안내

브랜치를 만든 뒤 아래처럼 안내한다.

- "`<브랜치이름>` 브랜치가 만들어졌습니다. 이제 개발을 시작하세요."
- `CLAUDE.md`(및 거기서 불러오는 `AGENTS.md`, `ui.md`)를 읽고 이 프로젝트의 **기술 스택과 컨벤션**을 짧게 정리해 다시 알려준다. 최소한 다음을 포함한다.
  - 스택과 버전 주의사항: Next.js 16(`proxy.ts`, `node_modules/next/dist/docs/` 확인), Tailwind CSS v4, Clerk Core 3, Neon + Drizzle, `@anthropic-ai/sdk`, `rss-parser`
  - 핵심 규칙: 인증 검사 위치, 사용자 격리, 가져오기 ≠ 저장, 중복 처리 등
  - UI 규칙: `ui.md` 기준(slate 회색 통일, blue 강조색 하나, `dark:` 짝)
  - 요구사항의 기준은 `PRD.md`이고, 검증은 PRD 9장 완료 기준 시나리오로 한다
- 마지막에 "개발이 끝나면 '완료' 또는 'done'이라고 입력하세요."라고 알려준다.

## 4. 완료 → 커밋 → main 병합

사용자가 **'완료'** 또는 **'done'**이라고 입력하면 진행한다.

1. `git status`와 `git diff --stat`으로 **변경된 파일 목록**을 보여준다.
2. 변경 내용을 보고 **커밋 메시지를 제안**한다. 기존 커밋처럼 한국어 한 줄 요약으로 쓴다(`git log --oneline -5`로 형식 확인).
3. 사용자가 확인하면 커밋한다. 메시지를 고치겠다고 하면 고친 메시지로 커밋한다.
4. `git switch main` 후 `git merge <브랜치이름>`으로 병합한다.
   - 충돌이 나면 멈추고 충돌 파일을 보여준 뒤 어떻게 할지 물어본다.
   - 원격에 푸시하거나 작업 브랜치를 삭제하는 것은 사용자가 요청할 때만 한다.

## 5. 작업 요약

병합이 끝나면 다음을 정리해서 보여준다.

- 작업 브랜치 이름과 병합 결과(현재 브랜치 `main`)
- 커밋 메시지와 커밋 해시
- 변경된 파일 목록과 각 파일에서 바뀐 내용 한두 줄
- 남은 일이나 확인할 점(예: `npm run build`/`npm run lint` 실행 여부, 푸시 여부)
